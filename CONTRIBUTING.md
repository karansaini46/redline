# Contributing to Redline Platform

First off, thank you for considering contributing to Redline Platform! It's people like you that make this tool such a great open-source project.

## Code of Conduct

By participating in this project, you are expected to uphold our Code of Conduct. Please be respectful and considerate to others.

## Getting Started

1. **Fork the repository** on GitHub.
2. **Clone the project** to your own machine.
3. **Install dependencies** with `npm install`.
4. **Copy the environment file** `.env.example` to `.env` and fill in your local variables.
5. **Run the development server** using `npm run dev`.

## How to Contribute

### Reporting Bugs

- Ensure the bug was not already reported by searching on GitHub under Issues.
- If you're unable to find an open issue addressing the problem, open a new one. Be sure to include a title and clear description, as much relevant information as possible, and a code sample or an executable test case demonstrating the expected behavior that is not occurring.

### Suggesting Enhancements

- Open a new issue with a clear title and description.
- Explain why this enhancement would be useful to most users.

### Pull Requests

1. **Branch naming**: Use a descriptive branch name (e.g., `feat/add-new-dashboard-chart` or `fix/auth-redirect-bug`).
2. **Commit messages**: Use Conventional Commits (e.g., `feat: added semantic search` or `fix: resolved issue with token expiration`).
3. **Tests**: Ensure all existing tests pass with `npm test`. Write new tests for new features.
4. **Linting**: Ensure your code passes linting via `npm run lint`.

Once your PR is open, a maintainer will review it and provide feedback. We aim to review all PRs within a few days.
